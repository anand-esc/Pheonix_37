# Master1: Frontend Architecture & UI Flows

This document details the frontend plan, architecture, and feature breakdown for the Phoenix Forensic Pipeline UI.

## Technology Stack
- **Framework**: React 18, Vite
- **Styling**: Tailwind CSS (custom deep/dark theme with `var(--bg-deep)`, `var(--accent-cyan)` etc.)
- **Routing**: `react-router-dom`
- **State/Context**: `RoleContext` for client-side Role-Based Access Control visualization.
- **API Connectivity**: `api.js` acts as a centralized REST client polling the FastAPI backend.

## Page Breakdown & Workflows

### 1. Case Dashboard (`/cases`)
- **Purpose**: Intake control and pipeline monitoring.
- **Features**:
  - Displays a summary list of all cases (queried from `/api/cases`).
  - Progress bar polling: Periodically polls `/api/case/{case_id}/status` to reflect real-time backend pipeline stages (e.g., Acquisition, Recovery, Encryption).
  - UI strictly reflects state derived from `pipeline_result.json` on the backend.

### 2. Evidence Page (`/cases/:id/evidence`)
- **Purpose**: Deep dive into recovered artifacts for a specific case.
- **Features**:
  - Lists individual recovered fragments.
  - Video Viewer: Utilizes HTTP range-requests to stream the lossless `.mp4` wrappers generated by the backend.
  - Metadata display: Shows confidence scores, codecs, timestamps, and offset sizes for forensic credibility.
  - Verification: Exposes the cryptographic hash comparison (Plaintext SHA-256 vs Vault Ciphertext).

### 3. Timeline / Analysis Page (`/cases/:id/timeline` & `analysis`)
- **Purpose**: Synchronize extracted video segments chronologically.
- **Features**:
  - Multi-camera temporal tracking. Maps distinct DVR channels against a UTC/IST unified timeline.
  - Renders events identified by the AI triage layer (e.g., YOLO object bounding boxes mapped to time offsets), ensuring no identification claims are made visually.

### 4. Report Page (`/cases/:id/report`)
- **Purpose**: Indian Legal Compliance Export.
- **Features**:
  - Reads the `custody_facts.json` and pipeline events.
  - Automatically drafts a BSA Section 63 compliant report.
  - Implements the Provenance Chain component, visually rendering the hash-chained ledger events for court defensibility.

## State Management & RBAC
- **`RoleContext`**: Provides the current operator's role (Investigator, Tech Expert, Auditor, Court) globally.
- Components conditionally render (or render as locked) if the context denies permissions, matching the backend's `X-Operator-ID` header validation.
