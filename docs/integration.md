# Subsystem Integration Guide: Acquisition Pipeline

**Component Owner:** Acquisition & Recovery Module  
**Scope:** Integration endpoints and architectural contracts for all interconnected subsystems (Detection, Ledger, Reporting, Frontend, Cryptography, AI Triage).

This document defines the strict integration boundaries and data contracts required to interface with the core forensic acquisition pipeline. No modifications to the `feat/acquisition-recovery` architecture are required to satisfy these contracts.

## 1. Format Detection and Vendor Adapters

Format detection routes dynamically based on vendor heuristics. The pipeline expects adapters to be implemented as lazily imported classes adhering to the `BaseAdapter` interface:

| Identified Vendor | Expected Module Import Path | Expected Class Identifier |
|---|---|---|
| Hikvision | `from backend.adapters.hikvision import HikvisionAdapter` | `HikvisionAdapter` |
| Dahua | `from backend.adapters.dahua import DahuaAdapter` | `DahuaAdapter` |

**Implementation Requirements:**
- Adapters must subclass `backend.core.interfaces.BaseAdapter`.
- Adapters must be constructible without initialization arguments.
- Adapters must be exported via the package `__init__.py`.

In the event an adapter is missing or fails instantiation, the pipeline enforces a safe fallback to the `GenericCarverAdapter` and records a `fallback = True` audit event. 

The pipeline ingests the `parse()` output (incorporating `channels`, `fragments`, and `metadata`) directly into the `EvidenceItem`. Adapters are strictly prohibited from implementing independent cryptographic hashing or encryption routines; the orchestrator handles all cryptographic operations centrally.

*(Optional Integration)*: Adapters may emit granular events by accepting `sink`, `case_id`, and `evidence_id` keyword arguments and invoking `backend.pipeline.events.emit`.

## 2. Immutable Ledger Subsystem

The ledger subsystem integrates via an event subscription model. The pipeline emits sequential, state-change events at every execution stage.

**Integration Example:**
```python
from backend.pipeline.events import InMemoryEventSink

sink = InMemoryEventSink()
# The ledger module subscribes to the sink to process emitted events
sink.subscribe(lambda e: ledger.write_event(e.event_type, e.model_dump(mode="json")))
run_pipeline(source, case_id=..., operator_id=..., out_dir=..., sink=sink)
```

Alternatively, the ledger module may implement the `EventSink` protocol (requiring an `emit(event)` method) and pass the instantiated object directly. Unhandled exceptions raised by a subscriber are logged but will not interrupt the core acquisition pipeline, ensuring failsafe evidence extraction.

**Key Cryptographic Anchors:**
- `intake_completed.sha256`: The foundational identity of the acquired image.
- `recovery_completed.recovery_hash`: The aggregated identity of all carved fragments.
- `encryption_completed.ciphertext_sha256`: The final encrypted state identity.

## 3. Reporting and Certificate Generation

Downstream reporting subsystems must ingest structured JSON artifacts generated by the pipeline. These artifacts act as the single source of truth for all forensic and operational facts.

**Primary Artifacts:**
1. `<out_dir>/custody_facts.json`: The authoritative facts ledger required for the BSA Section 63 certificate draft. Includes mandatory `limitations` enumerations. (Accessible via `backend.pipeline.custody.load_custody_facts`).
2. `PipelineResult.timeline`: Contains temporally correlated recordings and channel inferences, including critical `duration_basis` metrics (`declared_fps` vs. `assumed_fps`).
3. `<out_dir>/pipeline_result.json`: The comprehensive pipeline execution record (acquisition, detection, adapter, cryptography, timings, and events).
4. `<out_dir>/evidence.img.acquisition.json`: The isolated custody sidecar.

**Court-Defensible Reporting Constraints:**
Report generators must quote specific fields verbatim to maintain forensic integrity: `detection.rationale`, `fragments[i].confidence_rationale`, `vendor_info.validation_status`, `timeline.notes`, and `timeline.channels[i].rationale`. Derived durations must inherently state their underlying `duration_basis`.

## 4. Frontend Interface (API)

The frontend application interfaces with the pipeline exclusively via the FastAPI router defined in `backend/api/routes_acquisition.py`.

| Endpoint | Function |
|---|---|
| `POST /acquisition/runs` | Initiates an acquisition pipeline. Parameters: `source_path`, `case_id`, `operator_id`, `out_dir`, `device_info`, `encrypt`. Optional: `investigator_id`, `custodian_id`. |
| `GET /acquisition/runs` | Retrieves a list of active and completed jobs. |
| `GET /acquisition/runs/{job_id}` | Retrieves execution status, last event, and `bytes_read` (for progress tracking). |
| `GET /acquisition/runs/{job_id}/result` | Retrieves the finalized `PipelineResult` (Returns HTTP 409 if execution is pending). |
| `GET /acquisition/runs/{job_id}/events` | Retrieves the chronological event log. |
| `POST /acquisition/detect` | Executes a signature scan against a targeted file without initiating full recovery. |

*Implementation Note:* For prototype synchronization, polling the status endpoint at 1-second intervals is sufficient.

## 5. Cryptographic Integration

The pipeline orchestrator utilizes the centralized `CryptoProvider` strictly as dictated by the interface contract: it executes `hash_plaintext(data, stage)` immediately followed by `encrypt(data, case_id)` for every discrete fragment. 

Full-image encryption employs `backend.crypto.encryption.encrypt_file` utilizing the derived case Data Encryption Key (DEK). The orchestrator queries the DEK directly via internal provider hooks; future architectural iterations aim to encapsulate this operation entirely within a public interface method.

## 6. AI Triage Subsystem

Exported fragments are persisted as raw Annex-B `.h264` or `.h265` elementary streams within the `<out_dir>/fragments/` directory. Corresponding lossless MP4 containers are generated in `<out_dir>/playable/`. These artifacts are compatible with standard OpenCV and FFmpeg pipelines.

**Contextual Mapping:**
- Spatial and temporal context mapping is derived from `PipelineResult.timeline`. 
- Triage modules must assign `DetectionResult.fragment_id` to strictly match the `Fragment.fragment_id` of the source material.
- The `fragment_id` is deterministically derived from the fragment's cryptographic payload (`frag-<first 16 hex of SHA-256>`), ensuring absolute stability across environments and re-executions.
